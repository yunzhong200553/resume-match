# 接口参考

## 1. 上传并识别简历

上传文本型 PDF 或 DOCX，返回待人工确认的结构化候选结果。

### 请求

```http
POST /api/resumes/import HTTP/1.1
Content-Type: multipart/form-data
```

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `file` | form-data | binary | 是 | PDF 或 DOCX，最大 10 MB |
| `resumeId` | form-data | string | 否 | 导入到已有简历；省略时创建 Resume |
| `title` | form-data | string | 否 | 新建 Resume 标题；默认使用文件名去扩展名 |

文件约束：

- PDF：扩展名 `.pdf`，MIME `application/pdf`。
- DOCX：扩展名 `.docx`，MIME `application/vnd.openxmlformats-officedocument.wordprocessingml.document`。
- 服务端同时校验扩展名、MIME 和文件签名。
- 扫描版 PDF、图片、OCR 和整段简历文本粘贴不在本接口范围内。

### 调用示例

```bash
curl -X POST "http://localhost:8000/api/resumes/import" \
  -H "Accept: application/json" \
  -F "file=@zhang-san-resume.pdf;type=application/pdf" \
  -F "title=张三的简历"
```

### 成功响应

HTTP 状态：`201 Created`。完整示例见 [导入成功响应.json](示例/导入成功响应.json) 和 [低置信度导入响应.json](示例/低置信度导入响应.json)。

### 业务规则

1. 缺少业务必填字段时仍返回候选结果，不整体失败。
2. 缺失对象字段返回 `null`，数组字段返回 `[]`。
3. 必须识别字段缺失时，必须写入 `issues` 和 `requiredFieldsMissing`。
4. 原始文件在文本提取完成后删除。
5. 接口只创建导入记录、文本快照和候选结果，不创建 ResumeVersion。

### 错误响应

| HTTP | 错误码 | 场景 |
| --- | --- | --- |
| 400 | `EMPTY_FILE` | 文件为空 |
| 404 | `RESUME_NOT_FOUND` | resumeId 不存在 |
| 413 | `FILE_TOO_LARGE` | 文件超过 10 MB |
| 415 | `FILE_TYPE_NOT_SUPPORTED` | 非 PDF/DOCX 或文件签名不匹配 |
| 422 | `UNSUPPORTED_SCANNED_PDF` | PDF 无可提取文本 |
| 422 | `TEXT_EXTRACTION_EMPTY` | 文本提取结果为空 |
| 500 | `IMPORT_PARSE_FAILED` | 解析器异常 |

错误示例见 [扫描版PDF错误响应.json](示例/扫描版PDF错误响应.json) 和 [文件过大错误响应.json](示例/文件过大错误响应.json)。

## 2. 获取导入候选结果

根据 `importId` 获取候选结果，用于页面刷新后恢复校正状态。

### 请求

```http
GET /api/imports/{importId} HTTP/1.1
Accept: application/json
```

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `importId` | path | string | 是 | 导入记录 ID |

### 成功响应

HTTP 状态：`200 OK`。状态为 `needs_review` 时响应结构与上传接口一致；状态为 `confirmed` 时记录只读，不允许再次确认。

### 错误响应

| HTTP | 错误码 | 场景 |
| --- | --- | --- |
| 404 | `IMPORT_NOT_FOUND` | importId 不存在 |

## 3. 确认导入结果

提交用户校正后的完整 `ResumeDocument`，校验通过后写入 Draft。

### 请求

```http
POST /api/imports/{importId}/confirm HTTP/1.1
Content-Type: application/json
```

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `importId` | path | string | 是 | 待确认导入 ID |
| `document` | body | ResumeDocument | 是 | 用户校正后的完整文档 |
| `resolvedIssueIds` | body | string[] | 是 | 已处理的问题 ID |
| `overwriteDraft` | body | boolean | 否 | 是否覆盖已有 Draft，默认 `false` |

完整请求见 [确认导入请求.json](示例/确认导入请求.json)。

### 成功响应

HTTP 状态：`200 OK`。完整响应见 [确认导入响应.json](示例/确认导入响应.json)。

### 确认校验

- `document` 必须符合 [ResumeDocument](数据结构.md#4-resumedocument)。
- section ID 和 item ID 在同一文档内唯一且保持稳定。
- `order` 从 0 开始连续排列，同级不得重复。
- 所有业务必填字段必须非 `null`、非空字符串。
- `startDate` 不得晚于 `endDate`。
- `requiresUserAction=true` 的问题必须处理。
- 已有 Draft 且 `overwriteDraft=false` 时不得静默覆盖。

### 错误响应

| HTTP | 错误码 | 场景 |
| --- | --- | --- |
| 404 | `IMPORT_NOT_FOUND` | importId 不存在 |
| 409 | `IMPORT_ALREADY_CONFIRMED` | 重复确认 |
| 409 | `DRAFT_ALREADY_EXISTS` | 已有草稿且不允许覆盖 |
| 409 | `IMPORT_ISSUES_UNRESOLVED` | 必须处理的问题未解决 |
| 422 | `VALIDATION_ERROR` | document 不符合契约 |

## 4. 通用错误结构

```json
{
  "error": {
    "code": "IMPORT_NOT_FOUND",
    "message": "导入记录不存在。",
    "details": {"importId": "import_unknown"}
  },
  "requestId": "req_example"
}
```

客户端应根据 `error.code` 处理业务分支，不依赖中文 `message` 做逻辑判断。
