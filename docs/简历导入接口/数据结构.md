# 数据结构

## 1. 通用响应

成功响应统一使用 `data + requestId`，错误响应统一使用 `error + requestId`。

```json
{
  "data": {},
  "requestId": "req_example"
}
```

```json
{
  "error": {
    "code": "FILE_TOO_LARGE",
    "message": "文件大小不能超过 10 MB。",
    "details": {"maxSizeBytes": 10485760}
  },
  "requestId": "req_example"
}
```

## 2. ImportResult

| 字段 | 类型 | 必有 | 说明 |
| --- | --- | --- | --- |
| `importId` | string | 是 | 导入记录唯一 ID |
| `resumeId` | string | 是 | 所属逻辑简历 ID |
| `source` | SourceFile | 是 | 上传文件元数据 |
| `status` | ImportStatus | 是 | 当前导入状态 |
| `rawText` | string | 是 | 从文件提取的完整文本 |
| `structuredDocument` | ResumeDocument | 是 | 待确认结构化结果 |
| `fieldRecognitions` | FieldRecognition[] | 是 | 字段识别依据，可为空数组 |
| `confidenceSummary` | ConfidenceSummary | 是 | 置信度汇总 |
| `issues` | ImportIssue[] | 是 | 识别问题，可为空数组 |
| `unmappedFragments` | UnmappedFragment[] | 是 | 未映射文本，可为空数组 |
| `createdAt` | datetime | 是 | 创建时间 |
| `updatedAt` | datetime | 是 | 最近更新时间 |

`ImportStatus`：`processing`、`needs_review`、`confirmed`、`failed`。

## 3. SourceFile

| 字段 | 类型 | 必有 | 说明 |
| --- | --- | --- | --- |
| `type` | `pdf` \| `docx` | 是 | 文件类型 |
| `originalFileName` | string | 是 | 原始文件名，仅展示用途 |
| `mimeType` | string | 是 | 服务端检测的 MIME |
| `sizeBytes` | integer | 是 | 最大 10,485,760 |
| `pageCount` | integer \| null | 是 | PDF 页数；DOCX 为 `null` |

## 4. ResumeDocument

| 字段 | 类型 | 必有 | 说明 |
| --- | --- | --- | --- |
| `basicInfo` | BasicInfo | 是 | 基本信息 |
| `sections` | ResumeSection[] | 是 | 简历模块 |

“必须识别”表示服务必须尝试识别并报告结果，不表示缺失时接口失败。未识别时返回 `null` 并生成 `REQUIRED_FIELD_MISSING`。

### 4.1 BasicInfo

| 字段 | 类型 | 识别要求 |
| --- | --- | --- |
| `name` | string \| null | 必须识别 |
| `phone` | string \| null | 必须识别 |
| `email` | string \| null | 必须识别 |
| `nativePlace` | string \| null | 必须识别 |
| `birthDate` | string \| null | 必须识别，格式 `YYYY-MM` |
| `jobTarget` | string \| null | 可选 |
| `gender` | string \| null | 可选，保留原文 |
| `links` | Link[] | 可选 |

`Link` 包含 `label` 和完整 HTTP/HTTPS `url`。

## 5. ResumeSection 与 ResumeItem

`ResumeSection` 包含 `id`、`type`、`title`、`order`、`items`。

`ResumeItem` 包含 `id`、`order`、`fields`、`content`。

`type` 允许：`education`、`experience`、`project`、`skill`、`award`、`custom`。

- ID 创建后保持稳定。
- `order` 从 0 开始，同级不得重复。
- `content` 保存条目主要经历或原始描述。

## 6. 各模块字段

### 6.1 教育经历 `education`

| 字段 | 类型 | 识别要求 |
| --- | --- | --- |
| `school` | string \| null | 必须识别 |
| `major` | string \| null | 必须识别 |
| `startDate` | string \| null | 必须识别 |
| `endDate` | string \| null | 必须识别 |
| `gpa` | string \| null | 可选 |
| `ranking` | string \| null | 可选 |
| `courses` | string[] | 可选 |

### 6.2 工作/实习经历 `experience`

| 字段 | 类型 | 识别要求 |
| --- | --- | --- |
| `companyName` | string \| null | 必须识别 |
| `position` | string \| null | 必须识别 |
| `startDate` | string \| null | 必须识别 |
| `endDate` | string \| null | 必须识别；在职时为 `null` |
| `isCurrent` | boolean | 必有 |
| `department` | string \| null | 可选 |
| `location` | string \| null | 可选 |
| `manager` | string \| null | 可选 |

主要经历描述存放于 `content`，不能为空。

### 6.3 项目经历 `project`

| 字段 | 类型 | 识别要求 |
| --- | --- | --- |
| `projectName` | string \| null | 必须识别 |
| `role` | string \| null | 必须识别 |
| `startDate` | string \| null | 必须识别 |
| `endDate` | string \| null | 必须识别 |
| `techStack` | string[] | 可选 |
| `projectLink` | string \| null | 可选 |
| `responsibilities` | string \| null | 可选 |

详细经历存放于 `content`，不能为空。

### 6.4 技能 `skill`

| 字段 | 类型 | 识别要求 |
| --- | --- | --- |
| `skillName` | string \| null | 必须识别 |
| `proficiency` | Proficiency \| null | 必须识别 |

`Proficiency`：`basic`（了解）、`familiar`（熟悉）、`proficient`（掌握/熟练）、`expert`（精通）。无法判断时返回 `null` 并报告问题，不得擅自推断。

### 6.5 证书与奖项 `award`

| 字段 | 类型 | 识别要求 |
| --- | --- | --- |
| `name` | string \| null | 必须识别 |
| `awardedAt` | string \| null | 必须识别，格式 `YYYY-MM` |

### 6.6 自定义模块 `custom`

| 字段 | 类型 | 识别要求 |
| --- | --- | --- |
| `moduleTitle` | string \| null | 必须识别 |
| `moduleContent` | string \| null | 必须识别 |

## 7. FieldRecognition

| 字段 | 类型 | 必有 | 说明 |
| --- | --- | --- | --- |
| `targetPath` | string | 是 | 字段 JSON Path |
| `confidence` | Confidence | 是 | `high`、`medium`、`low` |
| `method` | string | 是 | 识别方法编码 |
| `sourceSpan` | SourceSpan | 是 | 原文位置 |

常用方法：`document_header_name_pattern`、`phone_regex`、`email_regex`、`keyword_and_location_pattern`、`keyword_and_date_pattern`、`url_regex`、`section_title_dictionary`、`organization_name_pattern`、`proficiency_keyword`。

`SourceSpan` 包含 `text`、`page`、`startOffset`、`endOffset`。PDF 页码从 1 开始；DOCX 的 `page` 为 `null`。

## 8. ImportIssue

| 字段 | 类型 | 必有 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 问题 ID |
| `code` | IssueCode | 是 | 问题编码 |
| `message` | string | 是 | 中文描述 |
| `severity` | Severity | 是 | `info`、`warning`、`error` |
| `targetPath` | string \| null | 是 | 对应字段；全局问题为 `null` |
| `candidates` | string[] | 是 | 候选值 |
| `requiresUserAction` | boolean | 是 | 确认前是否必须处理 |

`IssueCode`：`REQUIRED_FIELD_MISSING`、`OPTIONAL_FIELD_MISSING`、`LOW_CONFIDENCE_MATCH`、`MULTIPLE_CANDIDATES_FOUND`、`DATE_RANGE_INVALID`、`UNMAPPED_TEXT_EXISTS`、`DUPLICATE_ITEM_SUSPECTED`。

## 9. ConfidenceSummary

包含 `overall`、`highCount`、`mediumCount`、`lowCount`、`requiredFieldsMissing`、`sectionStats`。

存在缺失必识别字段或低置信度字段时 `overall=low`；否则存在中置信度字段时为 `medium`；其余为 `high`。

## 10. UnmappedFragment

包含 `id`、`text`、`guessedSectionType`、`sourceSpan`。`unmappedFragments` 非空时必须同时生成 `UNMAPPED_TEXT_EXISTS` 问题。

## 11. 确认结果

确认接口返回 `importId`、`resumeId`、`draftId`、`source=import`、`status=confirmed`、`updatedAt`。
