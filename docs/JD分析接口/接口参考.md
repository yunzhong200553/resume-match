# 接口参考

## 1. 创建 JD 分析

对指定不可变简历版本和用户输入的完整 JD 发起分析。后端创建 Analysis 后并行调用两个 Coze 智能体。

### 请求

```http
POST /api/analyses HTTP/1.1
Content-Type: application/json
```

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `resumeVersionId` | body | string | 是 | 已保存的不可变版本 ID |
| `jdText` | body | string | 是 | 用户直接输入的完整 JD，50-20,000 字符 |

完整请求见 [创建分析请求.json](示例/创建分析请求.json)。

### 成功响应

HTTP 状态：`202 Accepted`

```json
{
  "data": {
    "id": "analysis_01J8C3A7T5K9N2P4H6V1F0D8QX",
    "resumeVersionId": "version_01J8C2M7T5K9N3P1H6V4F8D0QX",
    "status": "processing",
    "providers": {
      "scoreAgent": {
        "status": "queued",
        "attempts": 0,
        "errorCode": null,
        "errorMessage": null
      },
      "suggestionAgent": {
        "status": "queued",
        "attempts": 0,
        "errorCode": null,
        "errorMessage": null
      }
    },
    "createdAt": "2026-09-21T14:00:00+08:00"
  },
  "requestId": "req_01J8C3A5M7N9P2H4V6K1F0D8QX"
}
```

完整响应见 [创建分析响应.json](示例/创建分析响应.json)。

### 业务规则

1. 接口只接受 `ResumeVersion`，不接受 Draft 或完整简历 JSON。
2. `jdText` 由用户直接输入或粘贴，不接受 JD 文件。
3. 返回 `202` 表示任务已创建，不表示分析完成。
4. 后端创建记录后并行调用两个 Coze 智能体。
5. 同一用户对相同 `resumeVersionId + jdText` 的重复提交可以创建独立 Analysis，以保留历史记录。
6. 创建失败不得修改 ResumeVersion 或产生优化版本。

### 错误响应

| HTTP | 错误码 | 场景 |
| --- | --- | --- |
| 404 | `VERSION_NOT_FOUND` | 简历版本不存在 |
| 413 | `JD_TEXT_TOO_LONG` | JD 超过 20,000 字符 |
| 422 | `JD_TEXT_TOO_SHORT` | JD 少于 50 字符 |
| 422 | `VALIDATION_ERROR` | 请求结构非法 |

## 2. 获取 JD 分析

查询任务状态以及已完成的契合度和建议结果。

### 请求

```http
GET /api/analyses/{analysisId} HTTP/1.1
Accept: application/json
```

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `analysisId` | path | string | 是 | Analysis ID |

### 成功响应

HTTP 状态：`200 OK`

- `processing` 示例见 [分析处理中响应.json](示例/分析处理中响应.json)。
- `completed` 示例见 [分析完成响应.json](示例/分析完成响应.json)。
- `partial_failed` 示例见 [分析部分失败响应.json](示例/分析部分失败响应.json)。
- `failed` 示例见 [分析失败响应.json](示例/分析失败响应.json)。

前端轮询建议：

1. `processing` 时每 2 秒查询一次。
2. 连续轮询最长 60 秒，之后停止轮询并允许用户手动刷新。
3. `completed`、`partial_failed` 或 `failed` 为终止状态。
4. 页面卸载后停止轮询。

### 错误响应

| HTTP | 错误码 | 场景 |
| --- | --- | --- |
| 404 | `ANALYSIS_NOT_FOUND` | Analysis ID 不存在 |

## 3. 重试 JD 分析

重试失败的 Coze 智能体。默认只重试失败 Provider，不重复调用已成功 Provider。

### 请求

```http
POST /api/analyses/{analysisId}/retry HTTP/1.1
Content-Type: application/json
```

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `analysisId` | path | string | 是 | Analysis ID |
| `targets` | body | string[] | 否 | `scoreAgent`、`suggestionAgent`；省略时重试所有失败项 |

请求示例：

```json
{
  "targets": ["suggestionAgent"]
}
```

完整请求见 [重试分析请求.json](示例/重试分析请求.json)。

完整响应见 [重试分析响应.json](示例/重试分析响应.json)。

### 成功响应

HTTP 状态：`202 Accepted`

```json
{
  "data": {
    "id": "analysis_01J8C3A7T5K9N2P4H6V1F0D8QX",
    "status": "processing",
    "retryingProviders": ["suggestionAgent"],
    "providers": {
      "scoreAgent": {
        "status": "succeeded",
        "attempts": 1,
        "errorCode": null,
        "errorMessage": null
      },
      "suggestionAgent": {
        "status": "queued",
        "attempts": 1,
        "errorCode": null,
        "errorMessage": null
      }
    },
    "updatedAt": "2026-09-21T14:01:30+08:00"
  },
  "requestId": "req_01J8C4B6M8N2P5H7V9K1F3D0QX"
}
```

### 业务规则

1. 只允许重试状态为 `failed` 的 Provider。
2. 重试复用原 Analysis，不新建重复记录。
3. 已成功的分数、匹配项和建议在重试期间保留。
4. 新建议按 `analysisId + sectionId + itemId + targetField` 去重。
5. 重试次数必须累加。

### 错误响应

| HTTP | 错误码 | 场景 |
| --- | --- | --- |
| 404 | `ANALYSIS_NOT_FOUND` | Analysis 不存在 |
| 409 | `ANALYSIS_IN_PROGRESS` | 当前仍在执行 |
| 409 | `ANALYSIS_NOT_RETRYABLE` | 指定 Provider 未失败 |

## 4. 处理条目建议

用户接受、拒绝或手工编辑一条建议。该操作只更新优化草稿，不修改原 ResumeVersion。

### 请求

```http
PATCH /api/suggestions/{suggestionId} HTTP/1.1
Content-Type: application/json
```

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `suggestionId` | path | string | 是 | Suggestion ID |
| `status` | body | string | 是 | `accepted`、`rejected` 或 `edited` |
| `editedText` | body | string \| null | 条件必填 | `edited` 时必须提交非空文本 |

请求示例：

- [接受建议请求.json](示例/接受建议请求.json)
- [拒绝建议请求.json](示例/拒绝建议请求.json)
- [编辑建议请求.json](示例/编辑建议请求.json)

### 成功响应

HTTP 状态：`200 OK`

```json
{
  "data": {
    "id": "suggestion_01J8C3D7T2K9N5P4H6V1F0M8QX",
    "analysisId": "analysis_01J8C3A7T5K9N2P4H6V1F0D8QX",
    "sectionId": "section_project_01",
    "itemId": "item_project_01",
    "status": "edited",
    "editedText": "使用 FastAPI 开发简历解析与版本管理接口，并使用 SQLite 完成结构化数据持久化。",
    "updatedAt": "2026-09-21T14:05:00+08:00"
  },
  "requestId": "req_01J8C5C7M9N2P4H6V1K3F0D8QX"
}
```

完整响应见 [编辑建议响应.json](示例/编辑建议响应.json)。

### 状态行为

| 提交状态 | 写入优化草稿的文本 | `editedText` |
| --- | --- | --- |
| `accepted` | `suggested` | 必须为 `null` |
| `rejected` | `original` | 必须为 `null` |
| `edited` | `editedText` | 必须为非空文本 |

### 错误响应

| HTTP | 错误码 | 场景 |
| --- | --- | --- |
| 404 | `SUGGESTION_NOT_FOUND` | 建议不存在 |
| 409 | `SUGGESTION_STATE_CONFLICT` | 建议已被其它请求更新 |
| 422 | `VALIDATION_ERROR` | 状态与 editedText 不匹配 |

## 5. Provider 错误处理

Coze 超时、返回非 JSON、字段缺失、评分越界、引用未知 ID 或产生无事实依据建议时，后端不得透传原始 Provider 内容。

标准错误见 [智能体服务错误响应.json](示例/智能体服务错误响应.json)。客户端只依赖 `error.code`，不依赖中文消息判断分支。
