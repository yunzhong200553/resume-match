# 字段约束冻结清单

冻结日期：2026-09-24  
契约版本：1.0.0

本清单是模块 B 实现、联调和契约测试的冻结基线。发生歧义时，优先级为：本清单、`数据结构.md`、`接口参考.md`、`接入概述.md`、README 概览示例。变更本清单必须单独评审，不得在功能提交中隐式修改。

## 1. 模块边界

- 分析入口只接收已保存且不可变的 `ResumeVersion` ID，不接收 Draft、上传文件或完整简历 JSON。
- JD 只接收用户输入或粘贴的文本，不接收文件或 URL。
- 两个 Provider 使用同一份脱敏后的版本快照并行执行，彼此不依赖。
- Provider 只返回候选结果；后端负责结构、ID、评分和事实边界校验。
- `ResumeVersion` 永不修改。建议处理和排序只作用于基于该版本创建的优化草稿。
- 只有用户显式保存时才通过现有版本服务创建 `source=optimized` 的新版本；`parentVersionId` 必须是被分析版本 ID。
- 导出只调用共享导出接口，输入仍为 `ResumeVersion ID + templateId + format`；模块 B 不新增导出实现，也不以 `analysisId` 导出。

## 2. 公共输入

### 2.1 CreateAnalysisRequest

| 字段 | 必填 | 冻结约束 |
| --- | --- | --- |
| `resumeVersionId` | 是 | 非空 string；必须指向存在的不可变版本 |
| `jdText` | 是 | string；去除首尾空白后长度为 50-20,000 字符 |

`POST /api/analyses` 固定返回 `202 Accepted` 和 `processing` 任务，不在创建响应中同步返回最终分析结果。同一 `resumeVersionId + jdText` 可创建多条独立 Analysis。

### 2.2 Provider 公共输入

固定包含 `analysisId`、`resumeVersionId`、`jdText`、`resumeDocument`。发送前移除姓名、电话、邮箱、所在地等个人信息；只保留 `jobTarget` 及与岗位直接相关的公开链接。

`resumeDocument` 必须复用现有公共契约：

- `basicInfo` 以 `backend/app/schemas/resume_document.py` 为准，不由模块 B 增加字段。
- `Section.type` 只允许 `education`、`experience`、`project`、`skill`、`award`、`custom`。
- section/item ID 必须稳定、非空且同层唯一。
- `order` 必须从 0 开始、连续且同层不重复。
- `fields` 为 `string -> string`；Provider 输入不得私自引入数组、布尔值或 null。
- `content` 为 string；Suggestion 的 `original` 必须与它完全一致。

## 3. Analysis

查询响应中的下列字段始终存在；不可用数据使用规定的 `null` 或空数组，不省略字段。

| 字段 | 类型 | 可空 | 冻结约束 |
| --- | --- | --- | --- |
| `id` | string | 否 | 后端生成的 Analysis ID |
| `resumeVersionId` | string | 否 | 被分析的版本 ID |
| `status` | enum | 否 | `processing`、`completed`、`partial_failed`、`failed` |
| `jdText` | string | 否 | 保存本次分析的完整 JD，不写普通日志 |
| `overallScore` | integer | 是 | 0-100；评分未成功时为 null |
| `scoreLevel` | enum | 是 | `high`、`medium`、`low`；评分未成功时为 null |
| `summary` | string | 是 | 评分未成功时为 null |
| `scoreBreakdown` | array | 否 | 评分未成功时为 `[]` |
| `itemMatches` | array | 否 | 评分未成功时为 `[]` |
| `missingRequirements` | array | 否 | 评分未成功时为 `[]` |
| `suggestions` | array | 否 | 建议 Provider 未成功时为 `[]` |
| `providers` | object | 否 | 必须同时包含 `scoreAgent`、`suggestionAgent` |
| `createdAt` | datetime | 否 | ISO 8601 |
| `updatedAt` | datetime | 否 | ISO 8601 |
| `completedAt` | datetime | 是 | `processing` 为 null；终止状态非空 |

分数等级固定为：80-100 `high`，60-79 `medium`，0-59 `low`。评分不得使用姓名、性别、年龄、出生年月、籍贯等个人属性。

## 4. 评分与匹配

`scoreBreakdown` 必须且仅能包含四个不重复维度：

| `dimension` | 固定 `weight` | `score` |
| --- | ---: | ---: |
| `coreRequirements` | 40 | 0-40 的整数 |
| `experienceEvidence` | 30 | 0-30 的整数 |
| `skillsCoverage` | 20 | 0-20 的整数 |
| `presentationQuality` | 10 | 0-10 的整数 |

四项 `weight` 之和必须为 100，四项 `score` 之和必须等于 `overallScore`。每项 `reason` 必须为非空 string。

`ItemMatch` 必须包含 `sectionId`、`itemId`、`level`、`matchedRequirements`、`reason`：

- section/item 必须存在于输入版本且归属正确。
- `level` 只允许 `high`、`medium`、`low`。
- `matchedRequirements` 始终为 string 数组，可为空，不得为 null。
- `reason` 非空且不超过 300 字。

`MissingRequirement` 必须包含非空的 `requirement`、`importance`、`reason`：

- `importance` 只允许 `required`、`preferred`。
- 重复 requirement 必须拒绝或去重。
- 缺失要求只能用于提示，不得自动写入优化草稿。

## 5. Suggestion

| 字段 | 类型 | 可空 | 冻结约束 |
| --- | --- | --- | --- |
| `id` | string | 否 | 后端落库时生成 |
| `analysisId` | string | 否 | 必须关联所属 Analysis |
| `sectionId` | string | 否 | 必须存在于输入版本 |
| `itemId` | string | 否 | 必须属于对应 section |
| `targetField` | string | 否 | 首版固定为 `content` |
| `original` | string | 否 | 必须与原始 `item.content` 完全一致 |
| `suggested` | string | 否 | 去除首尾空白后非空，且不得等于 `original` |
| `reason` | string | 否 | 非空且不超过 300 字 |
| `status` | enum | 否 | 初始为 `pending`；终态为 `accepted`、`rejected`、`edited` |
| `editedText` | string | 是 | 仅 `edited` 时为去除首尾空白后的非空文本 |
| `createdAt` | datetime | 否 | ISO 8601 |
| `updatedAt` | datetime | 否 | ISO 8601 |

Provider 不得生成 `id`、`analysisId`、`status`、`editedText` 或时间字段。`suggested` 不得新增输入中没有的技能、公司、项目、职责、成果、数字或时间。新建议按 `analysisId + sectionId + itemId + targetField` 唯一化。

建议更新固定为一次性状态流：

```text
pending -> accepted|rejected|edited
```

- `accepted`：`editedText` 必须为 null，优化草稿写入 `suggested`。
- `rejected`：`editedText` 必须为 null，优化草稿保留 `original`。
- `edited`：`editedText` 必须非空，优化草稿写入 `editedText`。
- 终态建议不可再次 PATCH；重复或并发更新返回 `SUGGESTION_STATE_CONFLICT`。

## 6. Provider 与状态汇总

每个 ProviderState 始终包含：

- `status`：`queued`、`running`、`succeeded`、`failed`。
- `attempts`：非负整数；创建时为 0，每次实际调用开始时加 1。
- `errorCode`、`errorMessage`：成功或待执行时为 null；失败时为脱敏后的非空值。

Provider 状态流固定为：

```text
queued -> running -> succeeded|failed
```

Analysis 状态流固定为：

```text
processing -> completed|partial_failed|failed
partial_failed|failed -> processing -> completed|partial_failed|failed
```

汇总规则：两个 Provider 均成功为 `completed`；仅一个成功为 `partial_failed`；两个均失败，或最终无可用结果，为 `failed`。

`partial_failed` 仍返回完整 Analysis 外壳：评分成功时保留评分侧字段、建议失败时 `suggestions=[]`；评分失败时评分侧字段为 null/空数组、建议成功时保留建议。

## 7. 重试与版本落地

- `targets` 可省略；省略表示重试全部 `failed` Provider。
- 显式 `targets` 必须是非空、无重复的 `scoreAgent`/`suggestionAgent` 数组，且每一项当前均为 `failed`。
- 重试复用原 Analysis，不创建新记录；成功 Provider 的结果保持不变。
- 被重试 Provider 清空旧错误并重新进入 `queued`；实际调用时累加 `attempts`。
- 用户显式保存优化结果时，复用现有版本创建服务；`source=optimized`，`parentVersionId=analysis.resumeVersionId`，原版本保持不变。

- 优化草稿的独立查询接口、草稿 ID 和拖动排序 API 尚未在 JD 接口文档中定义，后续必须以单独契约变更补充。
- README 中省略完整字段的分析响应仅为概览，不作为响应模型依据。
- 共享导出服务当前实现与导出文档的异步状态差异由模块 A 负责统一；模块 B 只依赖其公开接口。
