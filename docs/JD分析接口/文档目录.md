## 当前版本

- 文档版本：`1.0.0`
- API 前缀：`/api`
- 分析输入：已保存的 `ResumeVersion` 和用户直接输入的完整 `jdText`
- AI Provider：两个并行调用的 Coze 智能体
- 智能体 A：计算 JD 契合度百分比、条目相关度和缺失要求
- 智能体 B：针对现有简历条目生成文本优化建议

## 核心约定

1. JD 可以由用户直接输入或粘贴，不需要上传 JD 文件。
2. 只能分析不可变的 `ResumeVersion`，不得直接分析未保存草稿。
3. 两个 Coze 智能体接收同一份结构化简历与 JD，并行执行、分别校验。
4. 智能体输出必须是纯 JSON，不得包含 Markdown 代码块或解释性前后缀。
5. 契合度为 0 到 100 的整数，表示简历内容与当前 JD 的覆盖程度，不表示录用概率。
6. 建议只能优化已有条目的表达，不得新增技能、经历、结果或其它事实。
7. 所有 `sectionId` 和 `itemId` 必须存在于输入版本中，否则拒绝 Provider 输出。
8. 用户必须逐条接受、拒绝或编辑建议；系统不得静默覆盖原文。
9. 只有用户显式保存时才创建 `source=optimized` 的新版本，原版本始终不可变。
