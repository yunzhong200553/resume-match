# 测试记录（2026-09-30）

## 1. 测试目标

本轮测试用于验证 JD 分析、建议处理、Draft 所有权、optimized 版本链、数据库迁移和共享导出工作流，并回归模块 A 的简历导入、编辑、版本与导出能力。

重点验证本轮新增约束：

- Provider 初始化失败后进入终态，并可通过 retry 恢复。
- 并行 Provider 的输入相互隔离，且不包含个人基本信息。
- 优化 Draft 只能属于一个 Analysis，旧 Analysis 不得覆盖新版本草稿。
- 手工保存 Draft 后释放 Analysis 所有权。
- 从 Draft 创建版本后自动锚定 `baseVersionId`。
- `0002_analysis` 升级到 `0003_draft_analysis_owner` 时保留既有 Draft 数据。

## 5. 本轮新增测试

| 测试 | 验证内容 |
| --- | --- |
| `test_provider_initialization_failure_can_be_retried` | Provider 配置失败后 Analysis 为 failed；恢复配置后 retry 可完成，attempts 正确累加 |
| `test_parallel_providers_receive_isolated_document_copies` | 一个 Provider 修改输入时不会污染另一个 Provider 的文档副本 |

## 6. 既有关键回归覆盖

- Analysis 创建、查询、状态汇总和失败 Provider 重试。

- Draft 乐观并发控制和 Suggestion 事务回滚。
- 旧 Analysis 与跨 Analysis 草稿隔离。
- 原 ResumeVersion 不可变。
- optimized 版本的 `source`、`parentVersionId` 和文档内容。
- optimized DOCX 通过共享导出服务生成并包含建议文本。
- Alembic `upgrade head`、`downgrade base`、唯一约束与外键。
- PDF/DOCX 导入、文本解析、草稿编辑和版本链。
